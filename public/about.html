About

How it works

GeoLint uses geos-wasm to run the GEOS geometry engine as WebAssembly in your browser. GEOS provides geometry validity checks and operations such as equality, intersections and polygon unions. GeoLint combines these operations with checks for file structure, coordinates, geometry parts and line endpoints.

Rule definitions and classification draw on QGIS Topology Checker and Geometry Checker. GeoLint implements selected single-layer checks and groups them into data structure, geometry validity, geometry constraints, topology and spatial relationships, and attribute constraints. Processing diagnostics are shown separately. The browser offers geometry checks; attribute constraints are available through API and batch configuration.

File reading, parsing and inspection run in Web Workers. Findings identify the applicable rule, source records and available error locations. GeoLint reports problems without repairing the input. See the Rules reference for each check's scope and parameters.

Privacy

Your selected files, geometry and attribute values are processed locally in your browser. GeoLint does not upload them to a server. Reading, ZIP extraction and inspection take place in local Web Workers.

GeoLint does not save your files or inspection results in browser storage. Results remain in memory until replaced or the page closes. Reports are downloaded to your device and may contain filenames, feature IDs, error coordinates and overlap or gap geometry; handle them with the same care as your input.

The browser contacts the hosting server to load the website, engine and public sample. These asset requests are separate from your selected data. The included hosting code does not inject analytics or third-party scripts; hosting access logs and browser extensions depend on your environment.

Known limitations

GeoLint 0.1.0 is a development preview. Current limitations include:

  • Planar 2D only. Coordinates stay in their original units. CRS declarations are not validated, coordinates are not reprojected, and longitude/latitude measurements are not converted to metres. Z/M geometry is skipped.
  • Limited scope. No automatic repair, cross-layer checks, GeoPackage import or multi-layer archives. GeometryCollections are excluded from optional topology checks. A valid result covers only applicable selected checks and does not establish overall data quality.
  • Resource limits. Browser memory and rule budgets can stop large or complex inspections. There is no fixed file-byte limit. Cancelled or failed runs cannot produce a complete report.
  • Extreme Shapefile coordinates. Very large finite coordinates can overflow ring classification, omit polygon rings and produce incorrect validity results. This is a known issue pending correction.
  • Differences from QGIS. Rules follow documented algorithm semantics, but results are not guaranteed to match every QGIS version or GUI plugin error row. GEOS returns only the first validity reason for each geometry.
  • Compatibility still under review. Full desktop-browser, mobile-browser, spreadsheet CSV and large-file performance acceptance is incomplete. Public API and report formats may change.
