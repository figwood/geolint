Rules

Required rules are always enabled and execute when applicable and prerequisites are satisfied. Optional checks are selected individually. Categories describe what is checked, independently of rule IDs and execution groups. Run diagnostics describe processing limits and configuration problems, not data-quality violations.

Rule-001 · File format and size must be supported

Category · Run diagnostics

Accept .geojson/.json, .shp or .zip. Read GeoJSON as UTF-8 JSON; files are processed locally.

Required · Always enabled

Rule-002 · GeoJSON documents and features must be well formed

Category · Data structure

Require a supported geometry, Feature or FeatureCollection. Features must contain geometry. Legacy crs declarations are accepted as metadata; original coordinates are checked without reprojection.

Required · Always enabled

Rule-003 · Shapefile headers and records must be well formed

Category · Data structure

Validate SHP headers and record boundaries.

Required · Always enabled

Rule-004 · ZIP archives must contain one valid layer

Category · Data structure

Require one .shp layer and entries are validated. Validate framing and CRC; reject encryption, split archives, ZIP64, unsupported compression and duplicate filenames.

Required · Always enabled

Rule-005 · Geometry structures and coordinates must be valid

Category · Data structure

Require supported coordinate structures and finite positions. Lines require at least two positions; collections have a 64-level nesting limit.

Applies to · Point, line, polygon and geometry collection layers

Required · Always enabled

Rule-006 · Polygon rings must close

Category · Geometry validity

Each ring requires at least four positions; the first and last x/y positions must match. Input is never automatically closed.

Applies to · Polygon layers

Required · Always enabled · QGIS Geometry Checker documentation

Rule-007 · Coordinates must be two-dimensional

Category · Run diagnostics

Only consistently two-dimensional coordinates reach GEOS. Z/M coordinates are skipped; mixed dimensions fail parsing. No reprojection or spherical interpretation occurs.

Applies to · Point, line, polygon and geometry collection layers

Required · Always enabled

Rule-008 · Geometries must not be empty

Category · Geometry constraints

Null geometry, empty top-level coordinates and empty collections are skipped. A collection with an empty member is skipped as a whole after structural validation.

Applies to · Point, line, polygon and geometry collection layers

Required · Always enabled

Rule-009 · Shapefile record geometries must be well formed

Category · Data structure

Check record payloads, parts, coordinates and shell/hole structure. Malformed or ambiguous records fail parsing without repair.

Applies to · Point, line and polygon shapefile layers

Required · Always enabled

Rule-010 · Geometry types must be supported

Category · Run diagnostics

Support all seven GeoJSON geometry types and 2D SHP Point, MultiPoint, PolyLine and Polygon. SHP Z/M and MultiPatch records are outside scope.

Applies to · Point, line, polygon and geometry collection layers

Required · Always enabled

Rule-011 · Must not have invalid geometries

Category · Geometry validity

GEOS 3.13.0 uses GEOSisValidDetail with flags 0 on each supported nonempty 2D geometry. Return the first reason and optional location. Simplicity and spherical interpretation are outside scope.

Applies to · Point, line, polygon and geometry collection layers

Required · Always enabled · QGIS Topology Checker documentation

Rule-012 · Must not have duplicates

Category · Topology and spatial relationships

Detect topologically equal eligible records using GEOS, with no tolerance or snapping.

Applies to · Point, line and polygon layers (compared within the same geometry family)

Optional · Individually selected · QGIS Topology Checker documentation

Rule-013 · Must not have multi-part geometries

Category · Geometry constraints

Require at most one actual part. A Multi geometry with only one part passes; collections are excluded.

Applies to · Point, line and polygon layers

Optional · Individually selected · QGIS Topology Checker documentation

Rule-014 · Must not have dangles

Category · Topology and spatial relationships

Report coordinates with exactly one line part endpoint. Interior touches do not connect endpoints; no tolerance or snapping.

Applies to · Line layers

Optional · Individually selected · QGIS Topology Checker documentation

Rule-015 · Must not have pseudos

Category · Topology and spatial relationships

Report coordinates with exactly two line part endpoints, including closed lines and connections within multipart records.

Applies to · Line layers

Optional · Individually selected · QGIS Topology Checker documentation

Rule-016 · Must not overlap

Category · Topology and spatial relationships

Detect partial polygon overlaps using GEOS overlaps. Equality, containment and boundary contact do not violate this rule.

Applies to · Polygon layers

Optional · Individually selected · QGIS Topology Checker documentation

Rule-017 · Must not have gaps

Category · Topology and spatial relationships

Report enclosed holes in the union of valid polygons. The unbounded exterior and open channels are not gaps.

Applies to · Polygon layers

Optional · Individually selected · QGIS Topology Checker documentation

Rule-024 · Must not self-intersect

Category · Geometry constraints

Report each self-intersection within a line part or polygon ring. This additional constraint also applies to GEOS-valid lines.

Applies to · LineString, MultiLineString, Polygon, MultiPolygon. GeometryCollection is not expanded.

Optional · Individually selected · toleranceDigits: integer 0–15, default 8

Measurements use original coordinate units; no reprojection or automatic repair. Each finding retains its source part, ring, node or region.
