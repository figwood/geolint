How to use GeoLint

Inspect a file

  1. Choose a UTF-8 .geojson or .json file, a .shp file, or a ZIP containing exactly one Shapefile layer.
  2. Review the file preview, then select the optional rules you want to run. Required rules are selected automatically.
  3. Continue to the confirmation step and choose Start inspection. You can use Back to change the file or rules before the run starts.
  4. When the inspection finishes, review the summary, filter the results, and open rows for details. Check coverage shows rules that were skipped or could not be completed.
  5. Choose Download JSON or Download CSV to save the complete issue list. Filters and pagination do not limit the downloaded results.

Supported input

GeoLint accepts GeoJSON geometries and features containing Point, MultiPoint, LineString, MultiLineString, Polygon, MultiPolygon, and GeometryCollection values. Shapefiles support 2D points, multipoints, polylines, and polygons.

For a Shapefile ZIP, include one layer. A matching DBF can provide the data preview; PRJ files are not interpreted and coordinates are not reprojected. Unsupported dimensions, empty geometries, malformed data, and unsupported archive formats are reported as skipped or failed input.

See Known limitations for the full list of input and rule boundaries.

Understand the results

  • Valid: the applicable checks found no problems.
  • Invalid: a geometry or selected rule found a problem. The result includes the rule and location when available.
  • Skipped: the input is outside a check's supported scope, such as an empty or unsupported geometry.
  • Parse failed: the file or geometry could not be read.

Read the Rules reference for the checks, applicability, and parameters. A cancelled or failed inspection does not produce a complete report; choose another file or run the inspection again.

Find a source record

Feature indexes start at zero and follow the order of records in the input. Use the index shown in a result to locate the corresponding source record. IDs can repeat, so an index is the reliable way to distinguish records.

Export issues

Exports are available after a complete inspection. The file name is based on the input name and ends with _check_result.json or _check_result.csv. JSON preserves the report structure; CSV provides one row per issue. Both formats include all issues, including issues not visible on the current results page.
